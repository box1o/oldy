# Graphics Assets And Cameras

## Canvas Composition

Applications submit a retained `CanvasFrame` value with a `RenderFrameRequest`. The frame uses backend-neutral vertices, indices, batches, scissors, samplers, and logical texture/offscreen handles; it contains no duplicated glyph metadata side channel. Scene views targeting an `OffscreenTargetHandle` and the surface canvas are coordinated by one runtime frame and one surface present; UI types do not cross the GFX boundary.

`CanvasFeature` owns reflected cooked canvas shader generations, target-format PSOs, premultiplied-alpha state, dynamic vertex/index/uniform rings, samplers, and scheduler uploads. Canvas graph passes execute after scene views, declare every logical texture/offscreen sample, and leave the swapchain in present state; the runtime remains the sole acquire/present owner. UI colors are straight scene-linear values and are premultiplied in the shader. sRGB texture views decode automatically, while non-sRGB SDR swapchain formats receive explicit linear-to-sRGB output conversion. Rounded fills, per-corner borders, blurred shadows, image fill/contain/cover/natural fit, tint, nested clips, and physical-pixel scissors are carried by `ui::render` batches.

`ui::render::FontProvider` is the future shaping/atlas seam. The baseline `BuiltinFontProvider` deterministically decodes UTF-8, maps unsupported input to `?`, and uses a source-free procedural 5x7 ASCII atlas uploaded by the canvas runtime. It needs no packaged font file and makes no shaping, bidi, kerning, or MSDF quality claim; a FreeType/HarfBuzz/MSDF provider can replace it without changing `TextOp` or `CanvasFrame`.

`woki::gfx` owns both the cooked-product runtime and native graphics tooling. Native builds include descriptor composition, Tint compilation when available, texture/mesh building, and model import adapters, with their third-party dependencies linked privately. Emscripten excludes those host-only compiler and importer implementations while retaining runtime cooked-product APIs. An authored `gfx::RenderPipelineIR` describes renderer policy and feature order. It is not a frame RenderGraph and is not an `rhi::RenderPipeline` graphics PSO.

The module depends on core handles/hashes, asset VFS/products, platform file events, and RHI resource creation. JSON parsing uses pinned nlohmann/json. Native tooling can build pinned Tint from Dawn revision `9fd4a731474f66c1ce5465f9b13919ad7487315d`; Tint is private and excluded from Emscripten runtime builds.

The implementation file map follows subsystem ownership. `src/runtime/` contains bootstrap, frame execution, scene/view registries, presentation, recovery, and compute/readback facade units sharing only `src/internal/runtime_state.hpp`. `src/features/` contains common feature mechanics and focused mesh, depth, lighting, shadow, environment, temporal, post, presentation, and registration units. `src/graph/` contains validation, dependency analysis, culling, scheduling, lifetime allocation, transitions, dumps, and compile orchestration.

Descriptor and pipeline parsing, composition, compilation, product cooking, feature-config compilation, and candidate builds are side-effect free and may run on worker threads when their supplied VFS/compiler implementations permit it. `ShaderLibrary`, `RenderPipelineLibrary`, `LayoutCache`, and reload publication are externally synchronized. `BorrowedShader` and `BorrowedPipeline` retain immutable generations across publication and library destruction. Feature instances are immutable and concrete standard instances use explicitly injected runtime services; there is no process registry or renderer singleton. Shader modules and layouts may be marked with their last submission and manually pruned into a `DeferredReleaseQueue`; immutable borrowed generations prevent pruning while still referenced. Authored pipeline publication itself owns no GPU object and makes no GPU destruction claim.

Failures are returned or emitted as stable structured diagnostics. Reload is staged: a failed or stale candidate never replaces the last-known-good product. There is no fallback reflection when Tint is unavailable.

Pipeline source parsing is tooling/development-only. Normal runtime publication accepts a verified `asset::Product`, validates its bounded little-endian payload, canonical ordering, typed hashes, dependency path/hash pairing, enum ranges, counts, and trailing bytes, then composes instances through an explicitly owned `FeatureRegistry`. There is no global registry. Fallback selection uses ordered rules and normalized capability IDs; unresolved chains and cycles fail without replacing the current generation.

Canonical pipeline order is deterministic: feature dependencies (required and enabled optional dependencies) and authored extension order form the DAG, ties use `(feature id, instance)`, extension points and dependency paths are sorted, while fallback rules retain authored order because first applicability is semantic. Feature settings use overwrite precedence `referenced config < inline settings < quality profile`; all quality feature IDs and keys are validated even when an override disables a feature. `Multiple` features require a unique, stable source `instance`; single features reject instance names and repeats.

Required capabilities are the sorted union of enabled feature metadata and target requirements. Selection checks each pipeline's complete requirement set, applies the first ordered missing-capability rule, and rejects unsupported, unresolved, cyclic, or over-depth chains. `surface` is a semantic color target resolved by the host swapchain; all other target formats map through `ToRhiTextureFormat`. Samples are restricted to 1 or 4.

Descriptor entry points are authoritative: cooked interfaces contain only the declared stage/name pairs. Permutations are pipeline-constant identities backed by same-named WGSL overrides with validated scalar domains; they never rewrite source or alias static/skinned entry selection. The single-product CLI therefore refuses a multi-variant descriptor until an explicit variant is selected by a caller.

Tests cover JSONC descriptors, safe includes and source maps, deterministic variants/products/layouts, and stale/failed reload publication. Profile composition/compiler/cook separately from runtime module and layout cache misses; hashes make those boundaries observable without backend types.

The standard authored WGSL pack is installed at `share/woki/assets/shaders`; authored pipelines, feature configs, and quality profiles are installed at `share/woki/assets/render`. `standard.woki-shader-pack` remains a separate schema and stable shader namespace. WGSL validation is a separate, explicit Tint step and is never reported successful when Tint is absent. Emscripten applications may link the build-tree `woki::gfx_asset_preload` target to mount both trees. Installed consumers can include `share/woki/cmake/WokiGfxAssetPreload.cmake` to define the equivalent relocatable interface. `CreateShaderModuleFromAsset` and `RenderPipelineCompiler` are development/tooling source-loading paths; production code should publish verified cooked products through the corresponding libraries.

Shader semantic reflection and deterministic CPU/WGSL ABI generation are documented in [shader-abi.md](shader-abi.md). Installed schema URIs and editor associations are listed by `schema/catalog.json`.

Feature dependencies and extension-point constraints form a stable topological order independent of map iteration. Config files are typed data only, and quality profiles can only enable, disable, or override declared settings; neither format contains executable scripting, draw calls, resource IDs, barriers, backend state, or frame scheduling. Profile parse/compile/cook, feature factory creation, fallback selection, and runtime publication separately; canonical hashes expose each boundary.

Feature factories and registries must outlive compilation or composition calls; libraries are externally synchronized. A `BorrowedPipeline` and every `PipelineInstance` retain an immutable generation independently of later publication or library destruction. `RenderFeature::Setting` is the generic typed lookup boundary for compiled standard settings. `DeclarePipelineGraph` invokes each instance's `RenderFeature::DeclareGraph` in canonical compiled order and shares one typed graph-local blackboard. Mesh, depth, physical velocity, clustered lighting, Forward+, transparent, environment sky, histogram exposure, TAA/FXAA, presentation, shadow, bloom, and overlay features publish and consume typed records.

## Render Graph

`RenderGraphBuilder` is a single-threaded, frame-local compiler input. Its state is open builder, immutable definition, compiled graph, active frame, then retired frame. Handles contain graph identity and generation and cannot cross builders. Writes create explicit versions; reads always name one version.

Compilation consumes and detaches the complete definition; retained builders, pass builders, blackboard references and handles cannot mutate the compiled callbacks or metadata. It validates descriptors, access direction, pass/queue legality, attachments, resolves and copies. `CompileWithReport` accumulates independent validation failures where continuing is safe and returns structured `GraphDiagnostic` values with stable GRF code, stage and pass/resource names; dependency analysis stops when an invalid handle would make continuation unsafe. `Compile` remains the first-error convenience API. The graph CLI prints failed reports and JSON dumps include diagnostics. RAW/version-producer edges drive culling from exports, approved side effects and the latest published presentation, readback, persistent or temporal versions; WAR/WAW ordering is added only among retained passes. The result contains a stable schedule, logical queue/wave metadata, external acquire/release boundaries, same-state write barriers, queue dependencies, lifetimes and exact-key transient slots. JSON, DOT and Mermaid dumps do not serialize callbacks.

`GraphExecutor` owns callbacks and a bounded pool of physical transient sets through shared invalidatable state, so a frame that outlives its executor fails safely. Recording remains owner-thread serialized, but a submitted set is retired by its `SubmissionTicket` and reused only after `CompletedSubmission` reaches that ticket, allowing up to three GPU frames in flight. `GraphCommandBackend` is the narrow injectable recording seam for tests and command integrations: it covers frame/pass/copy/finish/submit/completion operations without recreating `rhi::Device`; graph resource and lifecycle validation stays in the executor. Static imports are supplied when declared; frame imports are explicitly bound. Temporal textures use a two-slot previous/current contract and rotate only after successful submission. Relative signatures resolve against the compile/frame extent, and dimensions differing from the compile extent are rejected so resize requires transactional recompilation. WebGPU executes on one physical queue: queue classes, ownership dependencies and async eligibility are advisory logical plans for future backends. Slot reuse does not claim native heap aliasing.

Texture uses and attachments may select mip, array-layer, and aspect ranges plus a view format/dimension. Remaining counts normalize against the logical descriptor. RAW/WAR/WAW hazards overlap ranges conservatively (`All` overlaps every aspect), while disjoint ranges do not create false dependencies. The compiler reports `GRF1028` for range bounds and `GRF1029` for illegal view format/sample combinations. The executor caches declared physical views; callback access to an undeclared view reports `GRF2005`. Attachment viewports and scissors are explicit metadata, enabling array-layer and mip atlas rendering.

`DeferredReleaseQueue::Retire` and `Collect` are owner-thread operations. Callers keep the queue alive across graph/cache replacement, collect with the queue completion watermark, and may inspect pending and unproven counts. Destroying pending ownership is only safe after device idle or during device teardown. A completion-registration or completion-callback failure is reported by `Queue::SubmissionTracking`; the watermark never guesses completion in that state.

Controlled runtime shutdown stops new requests, joins owned workers, drains publication queues, invokes the host's backend-neutral completion pump for the final `SubmissionTicket`, verifies the completion watermark, and collects every deferred queue before device-owned services are destroyed. Device-loss teardown is separate: completion is not assumed and explicit backend/device abandonment owns pending native resources.

## Runtime Resources

`RenderRuntimeServices` is an explicitly owned renderer service aggregate; it has no global singleton and owns no window, world, ECS, or file/decode work. It owns the frame-context ring, upload/readback schedulers, configured persistent buffer pools, diagnostics, and the shared `DeferredReleaseQueue` supplied to graph executors and replaceable GPU-object caches. All service mutation and publication is render-owner-thread work unless an asynchronous RHI callback is explicitly documented. Immutable registry borrows are lock-free snapshots; registry creation, publication, and removal are owner-thread-only.

`RenderRuntime` is the non-global application facade over these services. Its descriptor selects a backend and validation mode, bounds frames and workers in flight, names packaged asset roots/cache, and optionally supplies platform-neutral surface sources. The runtime transactionally creates and owns the RHI instance, adapter, device and queue plus asset services, libraries, caches, features, scenes, views, surfaces, graph history and diagnostics. Applications never receive a device accessor. `RenderDeviceFactory` and `RenderRuntimeAdvancedDescriptor` are explicit advanced injection seams for tests, recovery, and custom asset systems; ordinary packaged applications do not supply a device or PSO callbacks.

Sky, bloom threshold/downsample/separable blur/composite, tone mapping and grading, TAA, FXAA, luminance exposure, clustered lighting, and diagnostic fallback borrow immutable program generations prepared from packaged `ShaderProduct` data before `RenderFrame`. Runtime and graph callbacks never load descriptors, compose WGSL, invoke Tint, or create a PSO. `StandardFeaturePrograms` owns feature paths, entry points, binding construction, policy, and submission retirement; `RenderRuntime` only orders and submits features. Compatibility Forward writes SDR directly and declares no HDR/bloom intermediates. Surface outdated/lost/minimized state belongs to one `SurfaceHandle`; it never globally suspends offscreen, compute, or another surface.

Native builds with Tint expose explicit `woki_gfx_cooked_shaders`, `woki_gfx_cooked_pipelines`, `woki_gfx_cooked_materials`, `woki_gfx_cooked_textures`, `woki_gfx_cooked_meshes`, and aggregate `woki_gfx_cooked_assets` targets. They are not default `ALL` work; Studio/packaging opts into the aggregate. A default runtime build does not require `tint_api`. Cross/Emscripten builds consume `WOKI_GFX_PRECOOKED_ASSET_DIR`.

`FrameEpoch`, logical/content/residency versions, allocation IDs, and RHI submission epochs are distinct types. A frame context has available, recording, and submitted states. Its arena is cleared only when beginning an available context; a submitted context becomes available only after `Queue::CompletedSubmission` proves its ticket retired. Ring exhaustion applies backpressure and never waits for the GPU.

Persistent pools retain RHI buffers, use aligned best-fit generational suballocation, and delay frees carrying submission tickets. Pool diagnostics report committed/allocated/free bytes, largest free range, fragmentation, pending retirement, and the last known use. Vertex, index, material, GPU-scene, skinning, indirect, dynamic, upload, and readback classes describe policy and usage; they do not introduce mesh, texture, or material resource implementations.

Uploads accept already-decoded retained bytes and bounded queues. Normal uploads use mapped staging buffers and encoded copies, then publish residency only after completion and only if expected logical and residency versions still match. Public readbacks name logical buffers, textures, or offscreen targets and are lifetime roots in the same RenderGraph that declares their copy. `TryMap` returns an immutable retained `ReadbackLease`; releasing the ticket cannot invalidate an existing lease. Callback publication and ticket traversal are synchronized. Normal render-thread operation never waits for mapping or GPU completion.

Logical `ResourceState` and physical `ResidencyState` are independent. Device loss stops submissions, marks pools and pending physical work lost/rebuild-needed, and does not invalidate scene, view, surface, offscreen, mesh, material, palette, compute-resource, job, or readback identities. Recovery reconstructs libraries, caches, pools, programs, feature state, canvas state, histories, graph services, surfaces, and offscreen targets against a candidate device. Candidate validation must complete before the service generation is switched; failure discards the candidate without partially rebinding live services. Logical mesh, texture, and palette handles are reproduced exactly and their residency is rescheduled after publication. Surface outdated/lost handling only invalidates graph executables for that surface. Budget pressure, stale-version rejection, queue backpressure, allocation fragmentation, deferred-release depth, and fallback residency are observable profiling boundaries rather than silent policy.

## Application Facade

`<woki/gfx.hpp>` exports the stable runtime, scene/view, presentation, compute/readback, diagnostics, and logical asset-handle contract. Draw packets, physical bindings, pools, graph compilation/execution, and renderer-authoring APIs live under `<woki/gfx/advanced/>`; `<woki/gfx/advanced.hpp>` is the complete unstable umbrella. Runtime implementation headers live under `src/internal/` and are neither exported nor installed.

```cpp
gfx::RenderRuntimeDescriptor descriptor;
descriptor.assets.roots = {asset_root};
auto runtime = TRY(gfx::RenderRuntime::Create(std::move(descriptor)));

auto surface = TRY(runtime->CreateSurface({
    .source = window_surface_source,
    .width = window_width,
    .height = window_height,
}));
auto scene = TRY(runtime->CreateScene({.label = "main"}));
auto mutation = TRY(runtime->MutateScene(scene));
auto object = TRY(mutation.CreateObject({.mesh = mesh, .material = material}));
TRY(mutation.Commit());

auto view = TRY(runtime->CreateView({
    .scene = scene,
    .camera = camera,
    .pipeline = pipeline,
    .output = gfx::SurfaceOutput{surface},
}));
auto frame = TRY(runtime->RenderFrame());
```

Registered active views are rendered when `RenderFrame` receives empty spans; explicit scene/view spans support tools and partial updates. Each scene has an independent immutable snapshot carrying its `SceneHandle`; object/light arrays and views retain that identity, and a view can only consume its own scene snapshot. Stable view IDs own temporal history independently, and family IDs group preparation without merging scenes. Public completion values are opaque `GpuSubmissionId` values rather than RHI tickets.

Callbacks must declare every buffer and texture they use and retrieve those resources through `RenderGraphContext`; immutable PSOs, samplers and bind groups remain non-graph objects. `CommandEncoder()` is a trusted low-level escape hatch for backend integration, not a sandbox: the graph cannot prevent callback captures from accessing arbitrary RHI objects. Prefer the render/compute pass encoders and declared copy operations.

This milestone moves the render graph from `woki::rhi` to `woki::gfx`. Callers must replace the removed RHI builder/context/resource APIs with versioned `GraphTextureRef`/`GraphBufferRef` declarations, compile at a concrete frame extent, provide explicit external states and binding signatures, and recompile after resize. Actual WebGPU multi-queue recording and native heap aliasing remain future backend optimizations.

Camera poses, projections, normalized viewports, derived views, and orbit/fly controllers are plain state with no ECS or platform dependency. Camera projections are explicitly right-handed WebGPU zero-to-one depth; the existing core OpenGL projection helpers retain their original convention. Physical lens fields are metadata except for vertical-FOV/focal-length conversion and do not imply depth-of-field rendering.

## Render World And Visibility

`RenderScene` is the logical, backend-neutral mutation boundary. `SceneMutation` retains stable scene state plus the complete generational handle, rejects commit after destruction/reuse, and requires explicit `Commit` or `Cancel`; no destructor performs an implicit commit. The renderer applies sequence-ordered, generation/version-checked changes into per-scene immutable `RenderWorldSnapshot` generations. Hot object fields are SoA arrays with stable generational `RenderObjectId` indirection; dense indices are snapshot-local and never gameplay identities.

Views carry stable view/history IDs, current and previous camera state, explicit pipeline selection, masks and history invalidation flags. Families group related views without defining a global active camera. CPU visibility extracts WebGPU RH zero-to-one frustum planes, performs conservative sphere/AABB and mask tests, selects only resident LODs with hysteresis, and emits deterministic phase lists. The optional occlusion hook is explicitly conservative; the built-in path makes no occlusion claim. Contiguous worker batches use `task::Scheduler` when supplied and merge deterministically, with a synchronous fallback. Transparent packets preserve stable far-to-near object order while each object's submeshes still pass through `DrawPacketBuilder`.

`GpuScene` owns generation-checked logical-to-dense mappings and pooled instance, transform, light and material table allocations. Swap removal repairs mappings and retires logical removals against submission progress. CPU math is explicitly packed into fixed-size camera-relative records rather than copied as simulation structures. Dirty byte ranges collapse to whole-table uploads at a configurable threshold and are submitted as one upload batch. Device loss invalidates physical allocations while preserving logical records; `RestoreDevice` rebinds replacement runtime services and fully uploads them. Forward+ uses configurable X/Y/Z dimensions, logarithmic view-depth slicing, bounded per-cluster indices, and explicit overflow records. Compute-capable profiles dispatch on the graphics queue; compatibility profiles produce the same deterministic packed ABI on the CPU, without claiming asynchronous overlap. Feature preparation is a once-per-feature canonical-order hook over immutable world/views and does not add per-object virtual dispatch.

## Textures

`.woki-texture` schema 1 is strict JSONC. It identifies the asset and source URI and declares semantic, color space, 2D/cube shape, mip/streaming policy, maximum size, portable target policy, and sampler defaults. Native cooking reads the source through the asset VFS, uses private pinned stb_image and KTX-Software memory APIs, transcodes Basis input to the universal RGBA8 profile, and produces deterministic little-endian products. PNG/JPEG mip filtering is sRGB-aware and renormalizes normal maps. Product metadata and dependency identities are bounded; each mip is independently checksummed and represented by an asset product chunk, so stores may range-read the header and selected mips.

`TextureLibrary` retains generational logical handles across failure, reload, eviction, and device loss. Asset loading and product parsing occur through `AssetManager`; only already-cooked bytes reach `UploadScheduler`. Candidate generations publish after submission completion and only while their asset generation remains current. `ResolvedTexture` always reports fallback use explicitly. Standard white/black, flat-normal, magenta-error, cube, and legal depth resources are owned per library; there is no singleton. View and sampler caches use canonical value keys, retain physical ownership, track submission use, and retire through the shared `DeferredReleaseQueue`.

Residency currently uploads complete mip chains while recording the resident range and per-mip product locators. Budget eviction is LRU-like and only selects physical generations with no external resolved binding. Runtime block-compressed targets and virtual texturing are intentionally not claimed; RGBA8 is the universal target and the product/state boundaries preserve room for later profile-specific transcode and partial-mip streaming.

## Materials And PSOs

`.woki-material-type` and `.woki-material` schema 1 are strict JSONC. Type compilation validates selected passes, entry points, group 2 resources, overrides, and buffer bounds exclusively against cooked shader reflection, then emits an explicit WGSL host-shareable packing plan. Runtime property IDs are stable typed integers; bool parameters are encoded as `u32`, and no simulation-structure memcpy or string-key lookup is used while preparing materials.

`MaterialLibrary` separates immutable definition generations from mutable logical instance values. Authored values are rebased only when the source product generation changes; compatible runtime `Set` overrides are retained and take precedence. Frame-boundary type reload publication migrates compatible values by property ID and keeps the previous generation on candidate failure. `MaterialPreparation` batches dirty instances into the material pool transactionally, resolves semantic built-in texture identities, polls texture product/physical residency versions, and caches group 2 bindings by binding number, resource kind, product/allocation/residency, and sampler identity. `PreparedMaterial` carries the group 2 binding and a complete normalized pipeline request for mesh draw preparation. Materials classify render phase and expose PSO inputs but never draw or submit.

`PipelineCache` is owner-thread-only for every API and keys physical graphics/compute pipelines by normalized immutable shader product/variant/generation, stage entry-point IDs, override constants, layout, target signature, render state, and vertex schema semantics, never object addresses. Request and usage lookup share the same normalization. The current RHI creation path is wrapped as an honest synchronous Ready/Failed request; Pending is reserved for a future asynchronous factory. Used pipelines and material bindings carry submission tickets into the shared deferred release queue.

Asset setup calls `RegisterGraphicsAssetBuilders` with the application's `AssetServices`, VFS, and product resolver. This registers texture and material definition/instance builders without process globals. Material definition products depend on their shader and every default texture; instance products depend on the definition and every texture override, so `asset::ReloadCoordinator` invalidates the full dependency closure. `BuildOutput::generated_products` carries mesh-generated textures and material products. `AssetManager::PublishAtomic` validates transaction hashes, every resident external dependency, and the aggregate budget before advancing any generation. Studio recursively publishes the imported mesh child closure and dependency-graph edges before the mesh load returns.

## Meshes And Animation

`.woki-mesh-import` schema 1 is a strict native cooking descriptor. `ModelImporterRegistry` selects pinned fastgltf for glTF/GLB and pinned Assimp for compatibility formats; adapters resolve external buffers and images through asset URIs and copy backend-neutral `ImportedScene` records before importer destruction. Imported PBR factors, alpha mode/cutoff, double-sided state, texture semantics, embedded bytes, and external image dependencies produce deterministic generated material/type and texture records. Missing channels resolve to semantic built-ins rather than an untyped universal texture. External images cook through `TextureBuilder`; embedded bytes use an isolated memory-backed VFS. Runtime and Emscripten builds contain no importer dependency and consume only bounded little-endian mesh products; version 4 records stable generated material-instance IDs while retaining version 2/3 compatibility.

Hardware ray tracing, virtual texturing, and native multi-queue scheduling remain future renderer families rather than baseline compatibility paths.

Directional-light `intensity` is illuminance in lux at the receiver; the sun convention is approximately 100,000-120,000 lux under clear noon conditions. Point and spot `intensity` is luminous intensity in candela, with inverse-square attenuation and `range` as a smooth finite cutoff in metres. Light color is a normalized scene-linear RGB tint, not an additional hidden unit conversion.

Environment lighting is represented by a radiance cube, diffuse irradiance cube, roughness-prefiltered specular cube, and split-sum BRDF LUT. Sky visibility is independent from environment-lighting participation. Missing products resolve to explicit black/neutral fallback resources rather than disabling the lighting ABI.

Physical velocity is `RG16Float` UV motion generated for static and skinned meshes from current/previous object, camera, and palette transforms. TAA reprojects HDR color with depth and velocity, clamps history to the current 3x3 neighborhood, applies configurable feedback, and substitutes current color for cuts, resized/spawned views, or unavailable history. History rotates only from `OnSubmitted`; mobile and compatibility pipelines run physical FXAA without temporal history. Histogram exposure uses persistent adapted state and asynchronous readback, with a CPU adaptation fallback from the view's CPU log-average luminance and no per-frame GPU wait. Tone mapping optionally samples a 3D grading LUT and behaves as identity when none is resident.

Temporal history is keyed by stable view-history ID and semantic, uses two or three persistent slots, rotates only after successful submission, and invalidates on cuts, resize, pipeline/format changes, device loss, and age. Render and output extents are distinct view policy values; dynamic-resolution changes invalidate history rather than stretching it silently. HDR10/PQ remains an explicit future output encoding and is rejected until the surface/color-management path supports it.

`woki-mesh cook <descriptor> <cooked-root>` writes products to `<cooked-root>/mesh/<asset-id>.woki-product`; the aggregate native cook emits generic `manifest.wkam` and `studio.wkpkg`. Native builds cook `climbing.woki-mesh-import` and all generated children before packaging. Emscripten and install staging contain only the cooked manifest/bundle and runtime program metadata, never FBX or importer dependencies.

Imported transforms and animation data are canonical right-handed, +Y-up, -Z-forward metres. Matrices use column vectors (`world = parent * local`); adapter matrix copies and serialized matrices preserve Woki's column-major storage, and quaternions are serialized as `(x,y,z,w)`. Reflections reverse triangle winding and tangent handedness; the current pinned glTF and Assimp inputs are right-handed and therefore require no reflection.

Mesh products use a hashed stream/attribute `VertexSchema`, indexed triangle submeshes, coarse-first independently checksummed LOD chunks, geometric errors, meshlet bounds/cones, skeleton inverse binds, and animation keys. The canonical convention is right-handed, +Y up, camera forward -Z, meters, column-vector transforms, and final skin matrices `global * inverse_bind`. Quantization and compression are rejected until a corresponding runtime decode path exists.

The advanced GPU-driven extension is documented in `gpu-driven.md`. It adds temporal Hi-Z, conservative GPU visibility, immutable work bins, bounded indirect streams, asynchronous validation, and explicit capability fallbacks without changing public scene or asset APIs. CPU `DrawPacket` extraction remains the deterministic fallback and compatibility path.

`MeshLibrary` keeps logical handles stable while CPU products load and coarse LOD allocations upload through vertex/index pools. Draw extraction produces `DrawPacket` values; meshes never issue commands. `Animator` samples translation/scale linearly and rotations with shortest-path quaternion slerp, falls back to bind local transforms, evaluates parents before children, and publishes versioned dirty `SkinPalette` ranges through the skinning pool. Dynamic mesh handles are a separate capacity-oriented type and never mutate imported products.
# Runtime Preparation And Ownership

Runtime rendering consumes immutable cooked generations. Shader, pipeline, material, texture, mesh, and diagnostic products must be staged in the cooked manifest for shipping and web builds; authored-source cooking is a native development/build step only.

Upload requests retain `UploadPublicationToken` instances rather than addresses into resource records. A token validates content/residency versions, aggregates all pieces, and publishes `Resident` only after every required piece completes. Failed, stale, or device-lost generations are never drawable.

`ResourceRegistry` publishes immutable record generations under a read-mostly snapshot lock. Mutations remain owner-thread operations. Feature registration is startup-only once `FeatureRegistry::Freeze` has closed the registry, and runtime callers receive a const registry view.

Generic version, generational slot, sparse/dense handle, dirty-range, and dirty-bitset mechanics are provided by core. GFX retains only asset lookup, publication, residency, upload, and device-state policy around those primitives.

Frame preparation uses `PreparationFailurePolicy`: required upload/material failures abort before graph execution; optional failures produce structured diagnostics and allow prebuilt fallback or skipped draws. Draw callbacks must not cook assets or create feature/material/diagnostic pipeline generations.
